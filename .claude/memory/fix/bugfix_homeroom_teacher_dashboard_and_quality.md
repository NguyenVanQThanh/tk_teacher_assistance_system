### Summary
Fixed the homeroom teacher dashboard learning quality card and class selection flow. Specifically:
1. Dynamically connected real exercise attempt scores and grade cohort averages to the radar chart and pedagogical comments.
2. Synchronized homeroom class selection across the dashboard and homeroom management views with current academic year priority.
3. Enforced the business rule that a teacher presides over at most one homeroom class per academic year, adjusting academic seed data and frontend class filtering accordingly.

### Feature Specifications
- **Homeroom Class Scope**: Homeroom teachers can only manage and inspect classes where they are assigned as homeroom teacher (`homeroom_teacher_id`).
- **One Homeroom Class Per Academic Year Rule**: A teacher cannot be assigned as homeroom teacher to multiple classes within the same academic year.
- **Learning Quality Metrics**: Class radar axis values reflect real `StudentExerciseAttempt` average scores across subjects, compared against grade-level cohort averages for the same academic year.
- **Pedagogical Observations**: Vietnamese qualitative feedback notes dynamically generated by comparing class subject averages to grade benchmarks (e.g., above average, on par, needs improvement).
- **Academic Year Priority**: Class selection defaults to the active academic year (`2026-2027`) before previous cohorts.

### Bug & Feature Context
- **Issue 1**: The Learning Quality Card on `HomeroomTeacherDashboard` previously displayed hardcoded mock scores rather than querying real student submission averages.
- **Issue 2**: Selecting a homeroom class in the homeroom management screen (`TeacherHomeroomPage`) did not persist or synchronize with the dashboard card.
- **Issue 3**: `TeacherHomeroomPage` and `HomeroomTeacherDashboard` loaded all accessible teaching classes instead of filtering for homeroom classes, displaying multiple classes under the same academic year for one teacher.
- **Root Cause**: Backend dashboard endpoint did not integrate real-time attempt aggregation service for homeroom quality; frontend class loaders did not filter by `homeroom_teacher_id` or deduplicate by academic year.

### Solution & Technical Details
- **Backend Service**:
  - Implemented `LearningQualityService` in `backend/app/modules/exercise/services/learning_quality_service.py` to aggregate student attempt scores, compute grade cohort averages, and produce comparative observations.
  - Added `GET /api/v1/teacher/learning-quality` endpoint and integrated `LearningQualityService` into `GET /api/v1/teacher/dashboard` in `backend/app/modules/exercise/routers/teacher_dashboard.py`.
- **Frontend Integration**:
  - Updated `frontend/src/services/api.js` to support `class_id` query param in `teacherApi.getDashboard` and added `teacherApi.getLearningQuality`.
  - Updated `LearningQualityCard.jsx` to render a class dropdown when multiple homeroom cohorts exist.
  - Synchronized active class selection via `localStorage.getItem('selected_homeroom_class_id')` across `TeacherHomeroomPage.jsx` and `HomeroomTeacherDashboard.jsx`.
  - Filtered class dropdowns by `homeroom_teacher_id` and deduplicated by academic year.
- **Database & Seed Alignment**:
  - Distributed homeroom assignments in PostgreSQL: 12A1 (2026-2027), 11A2 (2025-2026), 10A3 (2024-2025) for Teacher Nguyen Van A.
  - Updated `backend/app/scripts/seed_academic_data.py` to enforce one homeroom class per year per teacher.
- **Testing**:
  - Added unit and API integration tests in `backend/tests/exercise/test_learning_quality.py` (all tests passing).
